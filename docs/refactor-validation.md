# 重构与 PC 布局验证记录

> 下方为开启 frameset 前的三栏阶段记录。当前 Windows 布局已调整为原生分栏：首页竖向 Tab＋列表，详情与发帖不再重复三栏。最新结果补充在本文末尾，旧浏览器列宽表不是原生分栏验收结果。

## 前一阶段：自定义三栏

本批完成设置页职责拆分、API 请求内部模块拆分、共享缓存元数据/保护规则、测试工具链隔离，以及首页、发帖页、详情页的桌面布局。PC 布局采用用户提供的参考图，内容和操作使用原有功能与接口。

## 实现范围

- `DesktopLayout` 保持中央组件父链稳定，在窗口宽度达到 1024px 时增加侧栏；整体限宽 1500px。
- 首页保留真实公告与四类列表，右侧加载现有公共热门讨论和板块。
- 发帖页拆分草稿、内容构建与发布生命周期；桌面右侧展示主动校验的预览，发布采用该预览的 HTML、标题、板块及草稿位置。
- 详情页保留中央滚动、评论锚点与图片测量边界，右侧复用已有相关主题。
- 窗口尺寸共享监听，返回页面时复测；原生编辑器处理单独调整窗口高度，工具栏限制到编辑列；板块选择弹层在 WebView 和 Skyline Portal 中均显式限宽。
- 根级 `resizable: true` 已输出到小程序构建产物。

## 后续阶段：Windows 原生分栏与左侧 Tab

- `app.config.ts` 同时开启 `frameset` 和 `resizable`；Windows 首页使用 60px 竖向自定义 Tab 与原有内容，详情/发帖不重复导航或完整三栏。手机底部 Tab 保留，macOS 宽屏仍使用此前三栏；不声称 macOS 支持原生 frameset。
- `PageScopeProvider`、每页 `PageViewportStore` 和捕获 owner 的导航/查询保持页面作用域。修复左栏排序列表首次访问/重挂时读取右栏 Current 的问题；HtmlRender 的异步图片和链接使用各自根 scope。页面高度改用原生页的 100%/flex 分配，不以整个窗口或猜测的导航高度撑开分栏。
- 原生分栏比例由微信管理，没有公开的自定义比例配置。页面实际宽度通过该页 resize/查询读取，不能把整体窗口宽度用作单栏宽度。

## 最新阶段：三档自适应首页导航

用户确认后的三档按桌面首页实际页面宽度计算：<640px 为 60px 图标栏；640～959px 为 160px 图标文字横排；≥960px 为 200px 图标文字导航与下方纵向热门板块。通用 `DesktopLayout` 仅接收 `railContent` 插槽，公开板块数据由首页组件及 `useDesktopHotNodes` 管理。Mac 右侧只保留热门讨论，不重复请求或展示 rail 的节点；话题页自身用于动态 Tab 的原有板块请求保留，没有改 API、缓存协议或持久化策略。

导航内容独立滚动，发帖入口置于滚动区之外；图标文字的导航、品牌、发帖及节点标题显式横向排列。断点和布局密度变化重新测量中央容器，不改列表父链、key、当前排序或实例。手机保留底部 Tab，Windows 详情/发帖继续没有重复 rail。
